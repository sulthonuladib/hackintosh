# 1401 flow, and running it without Windows

1401 ships as a Windows app, but the app is only a shell. Every step is a Python module, and the
modules we need run on Linux. This page follows the flow through the code and records how far the
Linux path gets on this machine.

## The Windows app is a shell

`1401.exe` is C# WinForms (`windows/App/`). It does no hardware work itself: it runs

```
engine\python\python.exe -u -m <module>      # cwd: engine\app
```

and streams the module's stdout into the window. The modules are `p1401` plus the pinned
`upstream/OpCore-Simplify` and `upstream/Hardware-Sniffer`.

| Window button          | Module                  | What it produces                                             |
| ---------------------- | ----------------------- | ------------------------------------------------------------ |
| Check this PC          | `p1401.scan`            | `Report.json` + `ACPI/*.aml`                                 |
| Build the Mac setup    | `p1401 build`           | `EFI/` + `.machine-profile.json`                             |
| Your BIOS steps        | `p1401.guide`           | HTML page of per-board steps                                 |
| Create the macOS stick | `p1401.usbwriter write` | FAT32 stick: `EFI/`, `com.apple.recovery.boot/`, `NullMoth/` |
| Update NVIDIA driver   | `p1401.nullmoth update` | newest driver package, SHA-256 verified, into `NullMoth/`    |
| Repair                 | `p1401.efidoctor`       | checks a built EFI directory                                 |

`app.manifest` asks for administrator because reading ACPI tables and writing a raw disk need it.
The C# layer's only Windows-specific jobs are the disk list (`Get-Disk`), the scan's WMI/native
facts, and the USB writer.

## Build pipeline (`p1401/engine.py: build()`)

1. Read `Report.json` (bounded to 16 MiB) and the ACPI directory; require a DSDT.
2. Load OpCore-Simplify headless and answer its ~40 console prompts from rules. A prompt with no
   rule stops the build (`UnknownPrompt`) instead of pressing Enter; the same prompt three times
   in a row also stops it (`EngineLoop`). Each answer is kept as a `Decision` with the text the
   engine printed before it.
3. `_nullmoth_gpu_pass`: mark GeForce RTX cards in the driver's PCI table compatible with macOS 15
   and 26 (v2.5.2: `SEQUOIA = ("25.99.99", "24.0.0")`, default 24) and let the engine continue
   instead of exiting on "unsupported GPU".
4. Compatibility check → pick the macOS version. v2.5.2 offers Sequoia and Tahoe for NVIDIA; older
   releases (including `main` before the v2.5.0 tag) cap it at Sequoia.
5. Hardware customization → disabled devices; the panel guard warns when a laptop panel is wired to
   a GPU without a macOS driver.
6. SMBIOS model, ACPI patches, kext selection; `iasl` compiles the SSDTs.
7. Download OpenCore, kexts and boot files (Dortania index + GitHub), build `EFI/`.
8. `p1401/policy.py` edits the config: AMD memory-map/IOMMU rules, NVIDIA small BAR for the
   installer, `boot-args`/SIP, no `boot-args` deletion, boot logs onto the stick, dedupe, and more.
   Every change is recorded with before/after and a reason.
9. `p1401/validate.py`: `ocvalidate` from the same OpenCore release (SHA-256 checked) plus file
   invariants (kext order, Lilu plugins, files on disk, non-empty SMBIOS fields) and boot-file
   hashes against the release archive. A validator that cannot run is a failure, not a pass.
10. `p1401/machine_handoff.py` writes `.machine-profile.json`: EFI file hashes, scan hash, SMBIOS,
    disabled devices, ACPI fingerprints.
11. `p1401/guide.py` reads the report **and the built config** and writes the BIOS steps.

## What runs on Linux

| Piece                                       | Linux status                                                                                                                                                                                          |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `p1401 build`                               | Works on this machine: OpCore-Simplify downloads `corpnewt/linux_iasl`, `macserial.linux` comes out of OpenCorePkg, and the validator loads `ocvalidate.linux`. Both Sequoia and Tahoe builds passed. |
| `p1401.guide`                               | Pure Python. Works.                                                                                                                                                                                   |
| `p1401.scan`                                | Supported (sysfs instead of WMI). The ACPI step copies `/sys/firmware/acpi/tables/*` with `sudo`, so it needs the password once.                                                                      |
| `p1401.usbwriter`, `p1401/rawdisk.py`       | **Windows only** (`Get-Disk`, `Clear-Disk`, disk-driver writes). On Linux we partition and format the stick ourselves and copy `EFI/` + `com.apple.recovery.boot/`.                                   |
| `p1401/hwcapture.py`, `p1401/fwres.py`      | Win32/WMI native facts. On Linux they return "unavailable"; the build continues and the capture is marked unbound.                                                                                    |
| CPUID/MSR, PCI resources, BIOS option names | Windows-only capture. The EFI does not depend on them; the 1401 Probe stick records the raw versions if we need them later.                                                                           |

The scan-evidence sidecar (`scan-evidence.json`) only exists for a run of `p1401.scan`. A report
from another collector (ours came from the probe's bundled Hardware-Sniffer) is still accepted:
`scan_evidence.load_for_report()` marks it `unbound` instead of failing.

## Runbook on this machine

The 1401 checkout is `.reference/1401` (git-ignored). Use the release tag, not `main`:

```sh
git -C .reference/1401 fetch --tags
git -C .reference/1401 checkout v2.5.2
```

1. **ACPI tables (root, once).** `/sys/firmware/acpi/tables/*` is mode 0400, so this cannot be read
   as the normal user. One `sudo` copy, named like the Sniffer names them:

   ```sh
   sudo sh -c 'set -e; d=/home/sulthonuladib/personal/hackintosh/devices/msi-pro-b650m-p/acpi; \
     mkdir -p "$d"; for f in /sys/firmware/acpi/tables/*; do [ -f "$f" ] || continue; \
     cp "$f" "$d/$(basename "$f").aml"; done; \
     chown -R sulthonuladib:sulthonuladib "$d"; ls "$d" | wc -l'
   ```

2. **Report.** The probe's tracked report is the record, but 1401's validator rejects the two
   root-level `ACPI Path` values the Linux collector emits (`\HPET`, `\AOD_`). Run 1401's own
   pinned collector and drop only those fields:

   ```sh
   cd .reference/1401
   python3 - <<'PY'
   import sys
   sys.path.insert(0, 'upstream/Hardware-Sniffer')
   import HardwareSniffer
   out = '../../build/msi-pro-b650m-p/scan'
   h = HardwareSniffer.HardwareSniffer(out, rich_format=False)
   h.u.head = lambda *a, **k: None
   h.hardware_info.hardware_collector()
   h.export_hardware_report()
   PY
   ../../scripts/report-for-1401.py \
     ../../build/msi-pro-b650m-p/scan/Report.json \
     ../../build/msi-pro-b650m-p/scan/Report.1401.json
   ```

3. **Plan only** (no network, proves the report + ACPI are accepted and shows the decisions):

   ```sh
   python3 -m p1401 plan ../../build/msi-pro-b650m-p/scan/Report.1401.json \
     ../../devices/msi-pro-b650m-p/acpi --macos 24 --json
   ```

4. **Build** (downloads OpenCore, kexts, iasl; output is git-ignored on purpose — it contains the
   generated SMBIOS identity). `--macos 24` is Sequoia, `--macos 25` is Tahoe:

   ```sh
   python3 -m p1401 build ../../build/msi-pro-b650m-p/scan/Report.1401.json \
     ../../devices/msi-pro-b650m-p/acpi ../../build/msi-pro-b650m-p/out-sequoia \
     --macos 24 --json
   ```

5. **Guide:**

   ```sh
   python3 -m p1401.guide ../../build/msi-pro-b650m-p/scan/Report.1401.json \
     ../../build/msi-pro-b650m-p/out-sequoia/EFI/OC/config.plist \
     --macos 24 --html ../../build/msi-pro-b650m-p/out-sequoia/guide.html
   ```

6. **Stick:** `usbwriter` does not run on Linux. The Sequoia stick already has
   `com.apple.recovery.boot/`; replace its `EFI/` with the built one, write
   `NullMoth/system-profile.json` from `.machine-profile.json`, and put the Mac companion
   (`1401-Mac-*.dmg`) in `NullMoth/`. Before erasing anything, compare `lsblk` twice: a wrong
   device is unrecoverable.

## Result on this machine (2026-10-22)

Both targets built on Linux with 1401 v2.5.2 and passed `ocvalidate` 1.0.9 with no issues:

| Target  | Version    | SMBIOS      | Audio                             | Where                                                             |
| ------- | ---------- | ----------- | --------------------------------- | ----------------------------------------------------------------- |
| Sequoia | `24.99.99` | `MacPro7,1` | `AppleALC` (layout default 98)    | `build/msi-pro-b650m-p/out-sequoia/`, copied to the Sequoia stick |
| Tahoe   | `25.99.99` | `MacPro7,1` | VoodooHDA, injected after install | `build/msi-pro-b650m-p/out/` (waiting for a Tahoe recovery)       |

Common decisions: Radeon 610M and the NVIDIA HDMI audio disabled, `MacPro7,1`, NVIDIA boot-args +
SIP `0x0A43` + `gfxrst=4` + `ResizeAppleGpuBars 0`, AMD `DisableVariableWrite` and
`AllowRelocationBlock`, boot logs onto the stick, boot-args never deleted from NVRAM. The full
record is in [`devices/msi-pro-b650m-p/build.md`](../devices/msi-pro-b650m-p/build.md).

## Open questions

- **Ada is unvalidated.** The RTX 4070 Ti SUPER is in the driver's table, but RTX 40 physical
  validation is still listed as pending. `ocvalidate` only says the config is well formed.
- **First boot is the open risk**: AMD memory map/IOMMU, the installer screen with a large BAR,
  and no NVIDIA driver during installation. The stick is set to leave OpenCore and Apple boot logs
  on the FAT32 partition.
- **Tahoe needs a Tahoe recovery medium.** Both sticks carry Sequoia recovery; the Tahoe EFI stays
  in `build/` until we fetch Apple's Tahoe recovery (~850 MB) onto a stick or make a Tahoe installer.
- **AMD CPU policy** (memory-map quirks, IOMMU off) still needs a boot test on this board.
- **iGPU.** The Radeon 610M has no macOS driver and stays disabled; the RTX is the only display
  route.
- **No Wi-Fi/Bluetooth** on this board; only the RTL8125 Ethernet kext is included.
